MC-10 Cassette Loading internal

Exact loader sequence and failure diagnosis for stock BASIC, MCX BASIC, XRoar, and MAME.

What each stage does

  1. CLOADM tells BASIC to enter the machine-language cassette loader.
  2. Playback supplies the audio data. It must begin while the MC-10 shows the loader search state, commonly S.
  3. After the transfer, BASIC displays the file name and returns to OK.
  4. EXEC enters the loaded image at its cassette execution address, normally $5000 for this project.

Manual XRoar sequence

xroar -machine mc10 -load-tape build/timing-calibrator.c10
  1. Focus the MC-10 display.
  2. Type CLOADM and press Return.
  3. Press Ctrl+T to open cassette controls.
  4. Select the input tape and press Play once while the loader is searching.
  5. Wait for the tape to stop and for BASIC to return to OK.
  6. Type EXEC and press Return.

Do not press Reset between CLOADM and Play. Do not start playback before entering CLOADM. A visible S means the loader is searching; it is not a successful transfer.

MCX BASIC sequence

The MCX-128 EPROM presents a boot menu before BASIC is available. Select 2, MCX BASIC (LARGE), then wait for the memory test and ROM-copy operation to finish. At the resulting prompt, use the same CLOADM, Play, wait for OK, and EXEC sequence.

The MCX-128 does not load or execute cassette data itself. It supplies memory mapping and firmware; BASIC and the MC-10 cassette routines perform the transfer.

The emulator-only direct ROM path bypasses the menu by patching the firmware selector. That image must not be programmed into a physical EPROM.

MAME sequence

mame.exe mc10 -ramsize 20K -cass build\timing-calibrator.c10

Enter CLOADM, press Return, then press MAME's default F2 tape-play key. After BASIC returns to OK, enter EXEC and press Return. Shift+F2 stops the tape.

The automated equivalent is scripts/mame-cassette-autoplay.lua. It uses post_coded with {ENTER}, calls cassette:play(), posts EXEC{ENTER}, and saves a PNG snapshot.

Failure diagnosis

Display or behaviorLikely cause
Reverse @ screenMCX cartridge profile is attached without a valid MCX ROM.
No cursor or no BASIC promptFirmware is still in its boot or memory-test path, or an incompatible direct ROM was selected.
S remains indefinitelyThe loader is waiting for audio, the tape was started at the wrong time, or the image format/audio path is incompatible.
File name and OK, but no test screenThe binary transferred successfully but EXEC was not entered or not accepted.
MCX128 ERROR followed by timer outputThe program executed on a machine without the MCX bank registers. This validates cassette execution and timer behavior, not MCX banking.

For the executable layout and timing interpretation, see the timer-compare procedure.
