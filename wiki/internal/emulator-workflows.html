Confirmed command-injection lesson

MAME's -autoboot_command requires a real Return character to submit a BASIC command. Passing the literal characters \n does not submit Return. In PowerShell, an actual line ending is represented by a double-quoted string such as "CLOADM`n"; single-quoted 'CLOADM\n' passes the backslash and letter n literally.

For repeatable tests, the project now avoids this fragile boundary. scripts/mame-cassette-autoplay.lua uses MAME's natural keyboard API:

keyboard.in_use = true
keyboard:post_coded("CLOADM{ENTER}")
keyboard:post_coded("EXEC{ENTER}")

The brace code {ENTER} is interpreted by MAME as the emulated Return key. It is not the same as the text sequence \n.

Cassette-control lesson

The MC-10 cassette interface does not provide a remote motor-control line. Loading therefore has three separate actions: enter CLOADM, start cassette playback, and enter EXEC after the transfer returns to BASIC. Starting playback before the loader is searching consumes the tape before the machine is ready.

The MAME Lua helper posts CLOADM{ENTER}, waits four seconds, calls cassette:play(), waits for the conservative transfer interval, posts EXEC{ENTER}, and captures the screen. The frame notifier subscription is retained globally because a local subscription can be garbage-collected after the autoboot script returns.

WSLg and CU lesson

WSLg X11 windows can be inspected with X11 tools such as xwininfo and the repository capture utility, but that does not guarantee exposure through computer use. A native MAME window was observed with a valid Windows process, title, and responsive state while the CU inventory still returned apps: []. This is an integration limitation of the active CU surface, not evidence that MAME failed to create a window.

Use emulator-owned screenshots for native MAME. Use the X11 capture path for WSLg XRoar. Do not infer display state from process existence alone.
